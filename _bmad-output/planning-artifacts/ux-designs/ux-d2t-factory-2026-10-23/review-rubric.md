# Spine Pair Review — d2t-factory

## Overall verdict

The pair is a usable contract: every `{token}` reference resolves, all 83 color tokens carry hex, the 24 components have matching rows in both files under identical names, and the board's lifecycle, modes and core states are committed in tables a story-dev can lift directly. The gaps are a few decisions left open that sit right on the product's thesis ("foreground human decisions"). The Done-stack collapse hides Decision seals, against the spine's own never-hide rule. The Evidence drawer has no content defined for a Decision seal. Escalation reason labels exist for only one of the four conditions. Fix those three, plus a cluster of medium consistency issues (amber's job, the "seal" naming overlap, the keyboard-shortcut conflicts, the incomplete CAP list), and the pair is strong.

## 1. Flow coverage — adequate

Checked: sources frontmatter → SPEC CAP-1…16 and the stage/escalation vocabulary in `pipeline-stages.md`, `review-policy.md`, `truth-layer.md`. UX-touching CAPs: 1, 2, 3, 4, 5, 6, 7, 8, 10, 11, 12, 13, 15, 16. Three Key Flows exist (live run, replay, recovery). Each has numbered steps, a bold **Climax** beat and a failure line. Flow 1 covers CAP-1 start, 2, 5/6/7, 8, 10 (taste disagreement), 11 (cut as failure path), 13 and 15. Flow 2 covers 15/16. Flow 3 covers CAP-1 resume and liveness. CAP-3 is present via the origin tag (no flow needed). Uncovered: rework, gate rejection, three of the four escalation conditions, SCAFFOLD failure, CAP-12 refusal.

### Findings
- **high** Only one of the four escalation conditions has a committed reason label (`Taste disagreement:`). Conditions 1–3 from `review-policy.md` have none: scope/intent change or spec ambiguity, irreversible/outward action (including the brownfield-only new-dependency page), and non-convergence or a slice over its time box. The SCAFFOLD-failure ESCALATION reason is also unnamed. Voice rules require the card and the chat message to reuse these strings verbatim, so story-dev will invent up to five labels (EXPERIENCE §Needs You type tags L80; §Voice and Tone L116, L125; §Pipeline stage → card lifecycle L67; EXPERIENCE §Component Patterns L144). *Fix:* add a reason-label table: `Scope change:` / `Spec ambiguity:` / `Irreversible action:` / `New dependency:` / `Non-convergence:` / `Over time box:` / `Taste disagreement:` / `Scaffold failed:`, each with one example body line.
- **medium** `/factory rework <note>` (CAP-1) and gate rejection have no flow, only table rows. It is never shown what happens when d2t does not approve Gate 1/2, which card returns, whether the Gate card leaves Needs You, or whether reviewers re-run (EXPERIENCE §Pipeline lifecycle L73; §Chat surfaces L104; §Key Flows). *Fix:* add a Flow 1 failure path or a short Flow 4: Gate 1 → d2t reworks the spec → SPEC returns to In Progress with `rework · Master d2t` → Gate 1 re-raised.
- **low** The CUT (CAP-11) and conflicted-merge (CAP-13) outcomes are compressed into one line each. The lifecycle table carries the detail, but the flows don't exercise the kept-vs-cut split or the resolutions body (EXPERIENCE L249, L247; L71–72). *Fix:* add one step each, or point the failure line at the lifecycle rows.
- **low** CAP-12 (second concurrent run refused when the run contract lists a shared DB; run-id claim fails) has no chat microcopy or flow (EXPERIENCE §Chat surfaces L97–106). *Fix:* add a chat-surface row with the refusal message.
- **low** Flow 3's heading names no protagonist or context, unlike Flows 1–2 (EXPERIENCE L262). *Fix:* "(d2t, mid-interview, after a panicked `/clear`)".
- **low** Flow 2's failure line ("live demo stalls → switch to replay") is the entry condition, not a failure of replay itself. Nothing covers a recording that is missing or fails to load (EXPERIENCE L260). *Fix:* add a `Recording not found` failure path that references the new state row (see §4).

## 2. Token completeness — adequate

Checked: all 83 `colors` (hex, including 8-digit alpha), 16 `typography` roles, 10 `rounded`, 23 `spacing`, 24 `components`. Ran a resolver over every `{path.to.token}`: 69 unique refs in DESIGN.md and 2 in EXPERIENCE.md (`{colors.amber}`, `{colors.holo}`), all resolve. No color is missing hex. Dark-only is declared, so no light/dark pairs are needed. The contrast table exists, and recomputing it from the tokens reproduces every stated ratio within ±0.1, apart from the two alpha-fill rows noted below.

### Findings
- **medium** The UNVERIFIED chip contrast is stated as 5.3:1 (`danger` on fill), but that is `danger` on bare `card-top`. Compositing `danger-a` (`#ff6a3d24`) over `card-top` gives **4.49:1**. That is below the spine's own 4.5:1 text floor, on an 11px label for the one state that says "this claim is not proven" (DESIGN §Contrast targets L396; YAML `danger-a` L54). *Fix:* measure against the composited fill. Either set the chip label to `danger-text` (8.3:1) or drop `danger-a` to `#ff6a3d1a` (4.75:1), then restate the ratio.
- **medium** Amber has two jobs across the spines. DESIGN says amber has "one job: the AT RISK edge" (DESIGN §Colors L376). EXPERIENCE also uses `{colors.amber}` for the Budget clock overrun `+m:ss over` (EXPERIENCE §Component Patterns L140), which has no component token and no measured contrast on `space-3` (7.45:1 computed). *Fix:* add overrun to amber's job list, add `budget-clock.over: '{colors.amber}'`, and add the `amber` on `space-3` row.
- **low** Three color tokens are orphans: `needs-text-sid` (opaque name, used nowhere), `gold-a1` and `gold-2` are defined but never referenced in prose or components (DESIGN YAML L40, L43, L51). The future-pip "dim brown" (L476) may be `gold-2` but doesn't say so. *Fix:* reference them where used (e.g. `replay-bar.pip-future: '{colors.gold-2}'`), and rename or delete `needs-text-sid`.
- **low** Shadows, glows, the inner highlight `rgba(255,255,255,.07)`, scan-line pitch, nebula opacities and the hologram treatment exist only as raw prose values (DESIGN §Elevation & Depth L430–433; §Colors L377). Implementers will hand-copy them, and they will drift. *Fix:* add component-level tokens (e.g. `slice-card.shadow`, `needs-you-card.shadow`) or a single shadow table.
- **low** `min-text: 11px` lives under `spacing` but is a font-size floor (DESIGN YAML L204; prose L414). *Fix:* express it as `{typography.tag.fontSize}`, or keep it as a note outside `spacing`.

## 3. Component coverage — adequate

Checked: the 24 YAML component keys, the 24 DESIGN §Components bullets and the 24 EXPERIENCE §Component Patterns rows. Names are identical across all three lists. Every behavioral row has a real rule, not a one-word description. Swept both files for other component-like names. Most are anatomy of an existing component (Master d2t seat, Copy button, run-id chip, slice-id chip, origin tag, `+N` deck, mini plates). The gaps are state variants and two rendering rules.

### Findings
- **medium** Slice card and Stage card state variants are defined behaviorally but not visually. Missing: the AT RISK amber edge with label `AT RISK · cut candidate`; the SIGNAL LOST danger border with `SIGNAL LOST · last seen 4m ago`; the evidence-selected gold outline with the `EVIDENCE ▸` tab (it appears only inside the Evidence drawer bullet); a cut slice in Done. The YAML has no token for any of these (DESIGN §Components L460–461, YAML L261–274; EXPERIENCE §State Patterns L165, L167; §Pipeline lifecycle L71). *Fix:* add a "Variants" line to the Slice card and Stage card bullets, with tokens (`slice-card.at-risk-edge: '{colors.amber}'`, `slice-card.lost-border: '{colors.danger}'`, `slice-card.selected: '{colors.gold}'`).
- **medium** The Verdict list renders only `APPROVE` and `reviewing…`. The appearance of a findings verdict or an `ESCALATE` verdict is unspecified. The source's first-line vocabulary is itself ambiguous (`VERDICT`, `STATUS`, or `APPROVE|ESCALATE`, `pipeline-stages.md` Agent protocol), and the spine says "verbatim" without resolving it (DESIGN L463; EXPERIENCE L145). *Fix:* list the allowed verdict words and map each to an existing token. Keep gold off agent verdicts.
- **medium** Sprite scale rules contradict their placements. The rule is "integer scale 2× / 3×", but the Master d2t seat is 128px (4× of 32, and the art is 32×30, not 32×32) and the conductor slot is 32px (1×). Column widths, notably In Review's 250px "four-sprite cluster", were sized on 48px placeholders while the final art is 64px (DESIGN §Pixel sprites L483, L487; §Needs You column L456; §Layout L418; memlog "layout grows to fit"). *Fix:* state the allowed scales per slot (1× header, 2× board, 4× seat) and say which column widths grow at final art.
- **medium** The Mode badge has no visual spec for `OFFLINE · reconnecting` or the 70% board dim, and the REPLAY dot color is unspecified (the mock uses `text-2`) (EXPERIENCE §State Patterns L175; DESIGN §Components L452). *Fix:* add an OFFLINE variant (dot `text-3`, no danger, no glow) and name the REPLAY dot token.
- **low** EXPERIENCE says Claim chips appear on "Gate card checks" (L146). DESIGN's Needs You card shows checks as plain text (`3 assumptions to check`, L469). "Gate card" / "GATE card" is also used as if it were a component name (EXPERIENCE L146, L168). *Fix:* decide whether gate checks carry chips, align both files, and write "Needs You card (GATE)".

## 4. State coverage — adequate

Walked the IA surfaces: Top bar, Column headers, Swimlanes (each column cell), Needs You, Evidence drawer, Replay bar, Live/Replay modes, chat surfaces. Covered well: cold load (no spinners), no runs, server disconnected, replay ended, empty Backlog before Gate 2, reviewer standing by, Done overflow, run complete, SIGNAL LOST, cut point, gate waiting, all three claim states, focus ring and focus return, reduced motion. Gaps are below.

### Findings
- **high** Done-stack collapse hides Decision seals, against the spine's hard rule. The deck is "not expandable in the POC" (EXPERIENCE L152) and "Seals stay visible on visible cards" (DESIGN L473). That conflicts with "Never removed" (EXPERIENCE L147) and the Don't "Fade, collapse away, or hide a seal when a card ages" (DESIGN L515). In Flow 1, Done holds six stage cards before any slice lands, so the `intake confirmed` and both Gate 1 seals collapse out of sight. The approved mock already does this with INTAKE. This cuts against CAP-15 "human-attributed events" and SPEC "every surface foregrounds human decisions". *Fix:* exempt sealed cards from collapse (collapse only unsealed machine stages), or render each collapsed seal as a clickable gold glyph on the deck.
- **high** Evidence drawer content for a Decision seal is undefined. Clicking any Decision seal opens the drawer (EXPERIENCE L147, L154, L182). However, the drawer spec, hero copy and HOOK FACT / CLAIM → PROOF anatomy describe only a claim being verified (DESIGN §Evidence drawer L475; EXPERIENCE L154). Nothing says what a gate, cut, merge, rework or intake seal shows: who, when, what was typed, the state-machine event, or gate evidence (CAP-14). *Fix:* add a "Decision" drawer variant. Hero: seal + decision line. Table: event · decided by · at · terminal response · run / stage · evidence checked. No claim chain.
- **medium** Keyboard primitives conflict. `Esc` closes the drawer generally (L154, L182), but the keyboard list scopes `Esc` to "replay mode only" (L186). The global `Space` and `←/→` shortcuts collide with native activation of a focused Copy button or checkbox, and with arrow-key movement inside the speed radio group the spine itself mandates (EXPERIENCE §Interaction Primitives L183, L186; §Accessibility Floor L228). *Fix:* make `Esc` work in both modes, and suppress the replay shortcuts while focus is on a button, checkbox or radio.
- **medium** Replay entry states are missing: loading a recording, recording not found or a malformed `/replay/<recording>` URL, the initial playhead state (paused at 00:00:00 or autoplay), and what an open drawer does when the playhead seeks before its source event (EXPERIENCE §Modes L91; §State Patterns L176). *Fix:* add four State Patterns rows.
- **medium** Placement of pipelined findings is undefined. When findings on S*n* arrive while Brix builds S*n+1* (`pipeline-stages.md` Agent protocol), the spine says the card goes "back to In Progress on findings" (L143), but the builder stays on S*n+1* and an agent works one card at a time (L151). Nothing says which column S*n* sits in, or how the retrigger round count (max 2, CAP-8) shows. *Fix:* define a `findings queued` marker on S*n* in In Review and a `round n/2` meta line.
- **low** There is no treatment for an abandoned or terminated run that never resumes. It is unstated whether the column headers and Master d2t seat stick when many lanes scroll vertically (EXPERIENCE §IA L39; §State Patterns). *Fix:* add a run-abandoned row and a sticky-header rule.
- **low** Copy failure (clipboard denied) is not covered. At `16×` replay, `aria-live` Needs You announcements may burst (EXPERIENCE L181, L230). *Fix:* fall back to selecting the command text, and coalesce or suppress announcements at 16×.

### Findings

The copies agree today, but this is where the §4 seal conflict hid. *Fix:* the behavior lives in EXPERIENCE Component Patterns and the visual in DESIGN; the other two places point to them.
- **low** EXPERIENCE points at the memlog ("memlog motion; idle 'look' is rendered", L138). Downstream consumers don't receive `.memlog.md`. *Fix:* state the rule inline.
- **low** DESIGN Colors and Layout prose restate hex and px values already in YAML (L372–377, L418), so there are two places to edit. *Fix:* in prose, name tokens and leave hex in YAML (optional; the editorial examples tolerate this).

## 7. Inheritance discipline — adequate

Checked: all `sources` paths resolve (`../../../specs/spec-poc-factory-plugin/{SPEC,pipeline-stages,review-policy,truth-layer}.md`, `mockups/key-dashboard.html`), and `design: DESIGN.md` resolves. CAP IDs are verbatim. Stage names, `merge OK`, Gate 1/2, budget clock, conductor, run contract and slice time box match the sources. The renaming of escalation queue → Needs You is justified in Voice. Component names are identical across both files. EXPERIENCE token refs resolve to DESIGN tokens.

### Findings
- **medium** Foundation's CAP list ("Serves CAP-1, 5, 6, 7, 10, 11, 13, 15, 16", EXPERIENCE L27) omits CAPs the spine implements and in places cites: CAP-2 (time-box default, L144), CAP-3 (origin tag, L139), CAP-4 (SCAFFOLD failure, L67), CAP-8 (findings loop and pipelining, L70), CAP-12 (run id / worktrees, L39). Story-dev traceability breaks. *Fix:* add CAP-2, 3, 4, 8 and 12.
- **medium** SCAFFOLD failure is tagged `ESCALATION` (L67), which contradicts the spine's own vocabulary rule that "the spec reserves *escalation* for the four conditions" (L114, `review-policy.md`). The user accepted this pending a spec fix, but the spine neither names the reason label nor tracks the spec change anywhere a consumer will see it. *Fix:* name the label (`Scaffold failed:`) and add the CAP-4/CAP-10 spec-change item to §Future.
- **medium** "Seal" is overloaded. The VERIFIED Claim chip is called a "solid gold seal" or "pixel seal glyph" (EXPERIENCE L163; DESIGN L466, L475), and Flow 2 step 4 "clicks its VERIFIED seal" (L256). Meanwhile Decision seal is a separate component reserved for human decisions. A consumer can't tell which component Flow 2 exercises. *Fix:* use "VERIFIED chip" everywhere and reserve "seal" for Decision seal. The glyph can be shared; the name should not be.
- **low** The spec defines verified as "hook fact **or evidence check** confirms it" (`truth-layer.md` Principle). The spines narrow this to hook facts only (legend `VERIFIED hook fact confirms`, DESIGN L453; Voice L119). Gate-evidence checks (CAP-14) have no display path. *Fix:* decide, then either widen the gloss or route evidence checks through the Decision-seal drawer (§4).
- **low** Name drift. The spec's `BUILD LOOP` appears as `BUILD` in the Stage track, header and resume list (DESIGN L459; EXPERIENCE L106) and as `BUILD LOOP` in the lifecycle table (L70). DESIGN sets `Quill` as the short display name (L504), but microcopy uses `Envoy Quill` (EXPERIENCE L116, L245). *Fix:* declare the display-name form per context (board label vs reason text) and note BUILD = BUILD LOOP once.

The desktop-only, horizontal-scroll behavior lives only in DESIGN Layout (L424), and the second surface (Claude Code chat) has no platform note. *Fix:* add one line to Foundation pointing to DESIGN L424, and note that chat formatting follows Claude Code's renderer.
