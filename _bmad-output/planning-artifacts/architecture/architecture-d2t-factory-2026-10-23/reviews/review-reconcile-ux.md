# Review: Architecture spine vs UX spines

Scope: UX requirements that need architectural support (data the board shows, event names, claim/lane states, drawer fields, Needs You commands, replay, modes, chat formats). Each finding lists where the UX asks for it, what the spine says (or doesn't), and a concrete spine edit. Line numbers refer to the files as of 2026-10-23. `EXP` = EXPERIENCE.md, `DES` = DESIGN.md, `SPINE` = ARCHITECTURE-SPINE.md.

**Counts:** Critical 3 · High 11 · Medium 13 · Low 8 (35 total)

A cross-cutting rule sits under several findings: **the dashboard and replay can only show what is in events.** AD-16 folds JSONL only, AD-18 records JSONL plus transcripts only, and AD-14 cuts facts down to a whitelist. So every field the board renders has to be written into some event's `data` by the CLI, usually by parsing the artifact on `factory done`. Findings C3, H1, M4, M8 and M9 are instances of this. Suggested umbrella edit: add an **AD-23 — Board data comes only from event `data`**, plus one table in `src/core/events.ts` that lists each kind's `data` schema.

## Critical

### C1 — Needs You cards show only `/factory resume`, but the reducer accepts decisions only from `approve/rule/cut/keep/merge/rework` with arguments
- **UX source:** EXP L109 ("Every tag shows the same command: `/factory resume <run-id>`"); EXP L142 (resume "is the command on every Needs You card"); EXP L145 (chat message ends with `/factory resume r-2c91`); DES L607 (Action slot shows "the command"); Flow 1 steps 4, 8 and 9 ("d2t approves / rules / gives merge OK in the terminal", with no command named).
- **Spine:** AD-6 L111–114 sets a closed decision set `/factory approve <gate>`, `rule <escalation> <choice>`, `cut <slices>` / `keep`, `merge`. The reducer accepts a decision only by consuming a *matching* `human_prompt`. The arch memlog says the "closed command set maps 1:1 to Needs You card types", which contradicts the UX "same command on every tag".
- **Gap:** The command the card tells d2t to type (`resume`) can't pass a gate. Nothing in either spine tells d2t the exact token for the gate (`1`? `gate-1`?) or the escalation ID (no escalation ID exists in the ID conventions at L295, and none is shown on the card). If d2t types "approve" or "looks good" after `resume`, AD-6 rejects it with `NO_HUMAN_PROMPT`, live, at the demo climax.
- **Suggested spine edit:**
  - AD-6: define the argument grammar: `/factory approve gate-1|gate-2`, `/factory rule <E-id> <free-text ruling>`, `/factory cut S5,S6` / `/factory keep`, `/factory merge`, `/factory rework [<target>] <note>`.
  - Add `E1, E2, …` (per run) to the IDs convention.
  - Define what `/factory resume` does on a parked run: it binds the session, then re-issues the open `ask_human` step, and the conductor prints the card *including its decision commands*.
  - Add `commands: string[]` to the `ask_human` step's `card` payload (AD-3 L79), generated by core per type: GATE → approve + rework; ESCALATION → rule; CUT → cut + keep; MERGE → merge; SIGNAL LOST → resume.
  - Raise a UX change request: the Action slot shows the decision command(s), with `resume` as the fallback for SIGNAL LOST, or when the session isn't bound.

### C2 — Intake confirmation has no typed `/factory` command
- **UX source:** EXP L82 (seal `intake confirmed · Master d2t`, plus a timeline pip); EXP L193 (a seal is created on "intake confirm"); EXP L209 / DES L627 (the Decision drawer's `terminal response` is verbatim); Flow 1 step 2 ("d2t confirms", with no command).
- **Spine:** The state diagram at L339 has `INTAKE --> ORIENT: intake_confirmed (human)`. AD-6 L111 has no intake command in the closed set. L115 allows free-form chat for INTAKE.
- **Gap:** Either the conductor records `intake_confirmed` from free chat, which is the exact LLM-asserted decision AD-6 exists to prevent, or there is no legal path at all. The Decision drawer for the intake seal also has no `human_prompt` to show as the terminal response. The budget clock starts from `intake_confirmed.ts` (AD-17), so the clock's origin depends on this decision too.
- **Suggested spine edit:**
  - Add `/factory go` (or `confirm`) to AD-6's closed set. It carries the confirmed limit and time box, for example `/factory go 2h` or `--timebox 30m`.
  - In AD-7, map `intake_confirmed` to `human_prompt`.
  - Flag the UX to add the command as the last chat line of INTAKE.

### C3 — Slice plan, gate checks, reason lines, findings and merge resolutions live only in artifacts, which neither the dashboard nor replay can see
- **UX source:** EXP L86 (slice cards are dealt into Backlog on Gate 2, with titles, roster and dependencies); DES L589 (slice-id chip and title); DES L596 (one verdict row per *assigned* reviewer); EXP L238 (`standing by`, reviewer not yet rostered); DES L603 (`3 assumptions to check`); DES L604 (MERGE re-verified rows and `RESOLUTIONS`); EXP L113 (reason line verbatim).
- **Spine:** AD-10 L163 puts all of this under `runs/<id>/artifacts/`. AD-16 L222 has the dashboard fold only `*.jsonl`. AD-18 L239 makes a recording "JSONL streams and snapshotted transcripts", with no artifacts. AD-2 L70 forbids the web app from reaching anything other than the server routes.
- **Gap:** No event carries the slice list, roster tags, dependency marks, assumption count, reason line or conflict resolutions. The Backlog can't be populated at all, and replay would show nothing even if the live server read the artifacts directly.
- **Suggested spine edit:**
  - New AD-23 "Board data comes only from event `data`". On `factory done`, the CLI parses the step's output file through `src/core/output.ts`, redacts it (AD-14), and records the board-relevant projection in the command event.
  - Define the `data` for each kind, at minimum:
    - `stage_completed{stage:SLICE_PLAN}` → `slices[{id,title,roster[],deps[]}]`
    - `gate_raised` → `{gate, title, checks[], assumption_count}`
    - `escalation_raised` → `{esc_id, label, line, slice?, stage}`
    - `stage_completed{stage:WRAP}` → `{branch, base, resolutions[{file,resolution}]}`
  - State that recordings need nothing more than the event streams.

    - `Over time box: {slice} at {elapsed} / {box} min.`
    - `Scaffold failed: {command} exits {code} …`

### H2 — The slice lifecycle and the board's column projection aren't in core
- **UX source:** EXP L60–68 (columns); L87 (Backlog → In Progress → In Review → Done; escalation moves the slice to Needs You); L94 and L237 (`findings queued`); L97 (human rework doesn't advance `round n/2`); L95 and L248 (AT RISK, cut); L238 (`standing by`); DES L589–594 (card variants).
- **Spine:** The state diagram at L336–359 is run-level only. AD-1 says every projection uses one reducer, but it gives no slice states and no card/column projection.
- **Gap:** The dashboard would have to invent the mapping from run state to columns, card variants and counters. That brings back the divergence AD-1 exists to prevent: the CLI's resume list and the board would disagree. There are two round counters, findings rounds and human rework, and nothing specifies them.
- **Suggested spine edit:**
  - Add a slice state enum to core: `backlog | in_progress | in_review | findings_queued | fixing | escalated | done | cut`, with flags `at_risk`, `signal_lost`, `findings_round` (0–2, advanced only by `FINDINGS` verdicts) and `rework_count`.
  - Add `src/core/board.ts`: a pure `project(state, now) → {lanes[{run, header, cells[column][cards]}], needsYou[]}`, used by the dashboard server and the CLI's resume list.
  - Add the slice-state diagram next to the run diagram.

### H3 — How hooks attach facts to steps (`corr`) is undefined, and agent-on-card, live spines, verdict verification and claims all depend on it
- **UX source:** EXP L197 (each agent is at one card at a time; reviewers cluster); DES L589 (the live spine lights while an agent works); DES L596 (a verdict row per reviewer with its own chip); Flow 1 step 6.
- **Spine:** AD-4 L92 ("Facts attach to commands by `corr`"); AD-7 L125–126 (matching by `agent_type`). The SubagentStart, Stop and Write hook payloads carry `agent_id`/`agent_type`/`tool_input`, not a factory `step_id`.
- **Gap:** The spine doesn't say how a hook computes `corr`. Matching by `agent_type` alone is ambiguous when two slices are in review with the same reviewer role (the pipelined S*n* re-check and S*n+1* review, EXP L94). A builder resumed through `SendMessage` (step kind `resume`) may not fire SubagentStart at all, so its sprite wouldn't attach to the card.
- **Suggested spine edit:**
  - AD-4: `corr` = `step_id`. The conductor must put `step_id` in the Agent tool's `description`. A `PreToolUse(Agent)` / `SubagentStart` fact records `{agent_id, agent_type, step_id}` from it, and the CLI keeps an `agent_id → step_id` map.
  - `output_written` correlates by `output_path`, which is unique per step because it embeds `step_id`.
  - For `resume` steps, `factory done` / `next` records `step_issued{agent_id}`, so attachment comes from the command stream.

### H4 — SIGNAL LOST: it must not fire while waiting on the human, it needs per-agent attribution, and its input isn't foldable
- **UX source:** EXP L234 (the card variant plus a Needs You SIGNAL LOST card; clears when heartbeats resume; dashboard only); EXP L235 (abandoned = never resumed, `last seen 2d ago`); Flow 3 L371 (`No heartbeat from the builder for 4m (3 missed).`); DES L591 (`· last seen 4m ago` on the specific card).
- **Spine:** AD-21 L268 (no event for 3×60 s **and** `claude agents --json` shows no live agent); AD-12 L183 (parked conductors stop); AD-20 L257 ("SIGNAL LOST and abandoned"); `run_abandoned` kind (L102) has no producer.
- **Gap:**
  1. A run parked at a gate for more than 3 minutes while d2t reads the spec emits no events and has no live agent, so it would show **SIGNAL LOST next to its own GATE card**.
  2. The UX copy names the role ("the builder") and the card. The rule is run-level.
  3. `claude agents --json` is an external input that isn't recorded. The fold then isn't a function of the events, and replay can't reproduce Flow 3.
  4. Nothing writes `run_abandoned`, and the port reclaim condition depends on it.
- **Suggested spine edit:**
  - AD-21: SIGNAL LOST applies only in *working* states (AD-12's set), never in `PARKED_*` or terminal states.
  - The projection names the last active step's agent role and card.
  - The reducer takes `liveAgents` as an explicit input next to `now`. Live, the dashboard polls for it. In replay it is `[]`, so SIGNAL LOST is purely the time gap, and the spine should state that.
  - Either drop `run_abandoned`, or add `/factory abandon <run-id>` to AD-6 and flag it to the UX. AD-20 then reclaims a port when the run is SIGNAL LOST for at least N hours or `run_abandoned`.

### H5 — Time-derived UI states need deadlines from the server, because the web app can't import core
- **UX source:** EXP L228 (CLAIMED → UNVERIFIED at 30 s); L186 (the Budget clock counts down, then `+m:ss over`); L190 (time box elapsed); L170 and L234 (`last seen 4m ago`); L268 (in replay, a claim may revert to CLAIMED on seek); L284 (seek, speed 1×/4×/16×).
- **Spine:** AD-2 L70 (web imports nothing from `src/`); AD-17 L230 (the reducer computes all clocks from `ts` + `now`); AD-21 (one constants module); AD-16 L222 ("pushes projection deltas"); AD-18 L240 (replay folds "on a playback clock"). No route or playback contract is given.
- **Gap:** Between events, the browser has to tick countdowns and flip CLAIMED to UNVERIFIED without core. It would either duplicate the thresholds, which breaks AD-21, or wait for a server push. In replay, play, pause, seek and speed are browser controls, but folding happens on the server, and with GET-only routes nothing defines how the playhead reaches the server.
- **Suggested spine edit:**
  - AD-16: the projection includes absolute deadlines, for example `claim.overdue_at`, `lane.signal_lost_at`, `budget.cut_at`/`ends_at`, `slice.timebox_ends_at`. The web app only compares them to its clock.
  - The server also pushes a delta when each deadline passes.
  - Replay: `GET /api/replay/<name>` returns the ordered events, each with its post-event projection and deadlines. The browser plays them on its own clock, steps or seeks by index, and computes only deadline comparisons.
  - Alternatively, `GET /api/replay/<name>/at?t=<ms>`. Pick one and write it down.

### H6 — Replay needs multi-run recordings, but AD-18 records one run at WRAP

### H7 — Tests-pass verification: the UX narrates "verified by hook" with the builder's own command, which AD-8 forbids as proof

### H10 — Bare `/factory` resolution and the resume list have no CLI contract
