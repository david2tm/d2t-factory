| 1 | **blocker-ish** (needs the human every health check after the first) | Every `contract.health` that restarts the dev server (each BUILD slice, then WRAP) stops and asks the human to `kill -TERM -<pid>` in their own terminal, or delete `runs/<run-id>/devserver.pid`. Cause: each sandboxed Bash command gets its own Seatbelt sandbox, and a command may signal only processes in its own sandbox. The dev server is spawned detached by one `factory check` call and outlives it. The next `factory check --restart` runs in a new sandbox, `process.kill(pid, 0)` gets `EPERM`, `probe` returns `refused`, and `stop` throws the `byHand` CHECK_FAILED (`src/cli/devserver.ts:107-125`). So the CLI can never stop a server it started in an earlier call. The `byHand` path was written for this case ("a sandbox can forbid signals to processes another command started"), but as a rare fallback; under the sandbox it is the normal path. Not caught by tests: `test/pipeline.test.ts` runs every check in one process, and the 8-1 sandbox conformance test covers git only, not signals. Same family as dry run 3 finding 1: a sandbox rule the CLI depends on that nothing tests. Direction (human, 2026-10-29): the factory should not depend on whether it can signal its own processes; the dev server should be easy to stop in any environment. Idea, not decided: a small supervisor that owns the server and is stopped through the run dir rather than by a signal (a `stop` file; it kills its own group, which it can always signal, and writes an `exited` marker), with liveness from a heartbeat file instead of `kill(pid, 0)`, and that also exits when its pid file or run dir goes away, so no orphans outlive the run. Add stopping the server to the sandbox conformance test. | run `e0kn`: `devserver.pid` → pid 95831 (`npx vite --port $PORT --strictPort`, started 05:03:07 at slice 1 BUILD health, presumably after the human stopped the SCAFFOLD server; not checked in the transcript); probe in this session: a detached `sleep` spawned by one sandboxed `node` call is signalable from that call (`kill(-pid, 0)` ok) and `EPERM` for `kill(pid, 0)`, `kill(-pid, 0)` and `kill(-pid, SIGTERM)` from the next call |
